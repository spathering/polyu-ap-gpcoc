## 项目目标

试实现一个用于线上多人跑团的通用工具，并探索相关的技术与协作方案。

项目处于原型验证阶段，已建立文档分类、索引和维护标准；当前文档进一步区分设计与工程，工程目录和施工占用统一在 hierarchy 中维护。

已建立 [Lua 简化编写同步内存实验原型](../engineering/lua-authoring-prototype.md)，完整线上跑团功能尚未实现。自定义规则与流程语言已确定为 Lua；已确认长期房间、主机权威及数值/引用/事件规则的设计方向；后端实现语言、Lua 版本与嵌入实现、具体架构和部署方式等仍待确定。

## 已确认的技术决策

2026-10-29，用户确认现阶段自定义规则与自定义流程统一使用 **Lua**，以运行时读取加载脚本文件和游玩中临场新增规则为需求背景。该决定替代此前 JS/Lua 并列选型的安排；不同时确定后端实现语言，也不表示动态加载、版本切换和流程恢复已经实现或验证。

Lua 宿主 API 已有同步实验子集；正式加载器、持久回执、版本化规则注册及进行中流程恢复仍待实施，见[后端、自定义能力与联机方案分析](<../../plans/project planning/backend-network-analysis.md#6-自定义规则成熟语言与有限宿主-api>)。

2026-10-30，用户确认**数据管理抽离为独立模块，首个测试版先实现并使用基于文件的管理模块**；数据库是否引入留待后续需求评估。该决定替代首测工程草案中的 SQLite 建议，不表示文件持久化已实现。具体端口、成组提交与恢复方案见[首测工程设计](<../../plans/project planning/first-test-engineering-design.md#53-独立数据管理模块与文件实现>)。

## 房间与规则的数据设计决策

2026-10-30，用户确认以下设计方向，作为后续实现约束：

- 房间是跨多日的长期存档单位。房间始终以主机数据为权威，全部游戏计算在主机进行，所有参与者共享同一剧情进度。
- 个人进度指事件在对应玩家或角色上的解锁、触发、知情及待办记录，附于各自相关容器，由主机保存与恢复，不产生玩家独立推进的世界副本。
- 数值表保存原始数值与当前持久状态；组合数值在需要使用或显示时调用主机规则计算。只读计算与产生业务效果的行动流程分开，规则可引用其他规则，须避免调用成环，并由流程配置明确应用顺序。
- 持有、装备、技能归属、状态承受和来源通过带类型的引用关系表达，关系可附标签或元数据；对象标签与数值分类各归相应数据定义。
- 规则容器保存规则引用，实例属性和参数由既有数值/引用容器及执行上下文提供；配置级行为定义把攻击、闪避、入场等事件映射到入口流程。

这些是已确认的设计决策，尚不表示正式存档、联机、规则加载和流程恢复已实现。详细结构及恢复边界统一见[数据与容器方案第 3.3—3.8 节](<../../plans/project planning/data-container-model.md#33-房间存档运行场次与连接生命周期>)，待实施内容继续在计划中维护。
