## 已有实现

`engineering/lua-authoring-prototype/` 是独立的 A0/A1 实验，尚未与线上跑团服务连接。三份规则以同一短注册入口声明稳定逻辑 ID、共享输入种类和回调。回调使用绑定当前上下文的 `r.check/r.damage/r.transfer/r.read`，无需返回效果列表；结果暂只接受 nil、布尔、有限数字及文本。

宿主在规则加载时只取得定义。调用时复制内存基线，收集实际读集，按调用顺序更新暂存状态；成功结束后检查前置版本和模型不变量，再一次替换内存状态并保存内存回执。写入使用对象允许集与 canWrite 的简化授权。捕获了宿主拒绝也会使整段不可提交。读取数据和返回回执均复制，防止通过修改副本改写宿主状态。

物品整叠转移保留 ID，部分转移生成新实例，更新相关背包及物品修订。数量只在物品实例保存，持有关系用单值映射表示。示例负重与伤害策略可通过宿主 options 注入替换；这只证明策略接口可替换，尚未实现版本化规则包委托。

预览运行同一回调并返回拟效果，不替换持久状态或写入回执。正式成功或失败的回执按身份、作用域和命令 ID 缓存；同 ID 不同规则来源/输入/前置条件拒绝，读取旧回执再次检查对象可见性。回执仅在本进程有效，没有跨重启保证。

## 宿主 API 与三个样例

`host.execute` 每次创建局部 `api` 表，把 `read/check/damage/transfer` 函数放入其中，再以回调第一个参数传入。样例命名为 `r`，这是可改名的普通参数；函数通过闭包关联本次暂存状态、读集、调用身份、效果与拒绝标记，调用方式为点调用，不传隐式 self。

规则文件外层 return 返回注册定义，加载时不掷骰或改对象。回调内部 return 决定业务输出，是否提交取决于执行成功与内核检查，不能以“有没有 return”判断是否修改数据。

| 当前 API | 实际行为与返回 |
| --- | --- |
| `r.read(id)` | 检查作用域和对象允许集，记录读集并返回副本；修改副本不写回 |
| `r.check(actor, skill)` | 读取技能，产生 1—100 骰面；返回 target/rolled/passed，宿主记录骰面 |
| `r.damage(actor, amount)` | 默认按护甲减伤并将 HP 截至零，更新暂存状态；返回 before/after/lost，可忽略 |
| `r.transfer(item, bag, quantity)` | 自动查找源容器，检查数量和容量；更新暂存数量/持有关系并返回目标实例 ID；底层可省略数量表示整叠 |

参数中的对象均使用 ID 字符串，由宿主读取；输入声明与回调参数按位置对应，不依据变量名推断。amount 是非负整数，quantity 是正整数。当前没有 `give/applyStatus/readData`、持久等待或通用规则包动作分派。

| 可运行样例 | 输入与正文意图 | 业务输出与测试场景 |
| --- | --- | --- |
| [01-check.lua](../../../engineering/lua-authoring-prototype/examples/01-check.lua) | 角色、技能；调用检定并取 passed | 返回布尔；技能 60 时骰面 25 成功、85 失败；访问失败属于 rejected，不是 false |
| [02-damage.lua](../../../engineering/lua-authoring-prototype/examples/02-damage.lua) | 角色、伤害；调用伤害，不写回调 return | 输出 nil，但效果仍提交；HP 9、护甲 2、原伤害 7，HP 变 4 |
| [03-transfer.lua](../../../engineering/lua-authoring-prototype/examples/03-transfer.lua) | 物品、目标背包、数量；调用转移 | 返回实例 ID；原叠 3 件、每件 400g、空目标容量 1000g，转 1 件生成新实例，转 3 件拒绝 |

03 的规则入口声明数量必填，底层函数的“省略即整叠”默认值没有在该样例入口暴露。整叠且容量足够时保留原 ID；部分转移保留原剩余实例并创建目标实例，重试返回相同提交结果。

原型的默认检定、伤害和重量算法仍在 host.lua 中，伤害/容量策略可通过宿主 options 注入；版本化规则包委托尚未实现。最终宿主 API、业务规则与通用内核的分层见[主方案](<../../plans/project planning/lua-authoring-facade.md#3-lua-宿主-api-与分层职责>)。

## 运行与本轮验证

使用 Lua 5.4，从原型目录运行 `lua tests.lua`。本轮实际使用独立临时目录中的 Python Lupa 2.8（Lua 5.4）执行 `tests.lua`，没有添加系统级或生产依赖。验证输出为 `PASS 56 assertions (Lua 5.4)`。

验证覆盖：检定成败、骰面记录、伤害及可注入策略、连续扣减读取暂存结果、脚本异常回滚、被 pcall 捕获的宿主拒绝仍阻止提交、读取副本不可写回、预览无状态修改、整叠与部分转移、容量拒绝、跨操作回滚、重复请求稳定 ID、同 ID 改参数冲突、对象版本冲突、非有限输入、隐藏对象/跨作用域/禁止写入、撤权后旧回执、操作数限制及非法返回值。

这是实际同步内存执行器的测试，不是数据库、联网或故障恢复验收。05 的简化流程仍为纸面稿，未运行等待或审批。

## 明确限制

- 无数据库、持久回执、审计落盘或重启恢复；内存原子性不等于数据库事务与崩溃原子性。
- 无网络身份绑定、角色/字段/动作级权限、授权投影、状态/地图功能、规则注册表和动态覆盖版本管理。
- 没有生产随机服务与失败重试的持久随机记录；成功回执重放不重新执行，进程终止后不保证原骰面。
- 共享输入声明只生成本地位置参数验证，不生成 JSON Schema、表单或 Agent 动作目录。
- `canWrite` 与对象允许集由受信调用端提供，不是接收玩家自报权限的公共 API；详细 diagnostic 只供实验调试，不是玩家可见错误契约。
- 仅限制宿主操作数，无 CPU/内存隔离或 Lua 指令超时。受控加载环境也不构成安全沙箱；只能运行主动信任的样例。
- 原型禁止重入写入，尚不支持并行执行与真实并发竞争测试；持有映射只覆盖非嵌套物品，不处理容器循环。
