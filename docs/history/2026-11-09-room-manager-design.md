## 1. 目标、依据与阶段

用户已确认：GUI 放在 engineering 之外，采用独立桌面工具，仅通过宿主接口查询和处理运行房间；首版实现现有接口支持的管理功能与数据变化观察，完整变更历史及存档管理后续补齐。首版已在 `tools/room-manager/` 实施，当前能力与操作见[工程入口](../current/engineering/room-manager.md)和[验收报告](../../tools/room-manager/legacy/winforms/docs/acceptance.md)。本文件保留分期设计依据，完整历史与存档扩展仍待实施。

工具名 Room Manager，根目录 `tools/room-manager/`。独立进程、源码、依赖说明、构建、测试、发布与用户配置；宿主不依赖此工具。首版面向 Windows x64、本机已运行宿主和 KP 管理账号，一次只连接一个宿主。玩家账号登录后显示“需要 KP 权限”，不加载管理数据；可在以后另设受限观察模式。

首版不启动/停止宿主、不直接访问房间文件、不导入 Python 后端模块、不启动第二个 Host、不依赖工程虚拟环境或规则包桌面。关闭 GUI 不停止房间；工具可复制到其他目录运行。当前宿主仍仅监听本机，不能将地址输入框解释为已经支持公网部署。

核查基线：2026-11-05 的 server.py、host.py、operations.json、浏览器 SDK 与现有 WinForms 构建脚本。这里只重用协议，不引用其源码路径作为运行依赖。

## 2. 技术与实现对照

首版采用 C# / Windows Forms 桌面路线，HTTP 与 WebSocket 在原生客户端内完成，不嵌入网页或另起本地代理。使用 System.Net.Http.HttpClient、CookieContainer、ClientWebSocket 与异步网络任务；UI 线程只做呈现。目标 .NET Framework 4.8、x64，R0 必须验证本机编译引用、运行时、中文字体/DPI、Cookie 与 WS 行为并记录版本。既有安装器的构建方法是参考，工具不引用它的源码或运行目录。若探针不通过，先更新选型与依赖记录，再进入依赖该选型的任务。

2026-11-05 已完成本机 .NET Framework 4.8 与 HTTP/WS 探针，选型已用于首版。首版尽量使用系统框架；新增第三方库需记录版本、用途、许可证和可复现安装方法，不修改宿主 dependency-manifest.json 或 launcher-config.json。

实际目录见 [hierarchy](../current/engineering/hierarchy.md) 与[模块说明](../../tools/room-manager/legacy/winforms/docs/development.md)。首版只生成一个独立 EXE，用例协调暂由 MainForm 承担，不保留空的 Application 目录。列表采用每页 500 项的本地分段呈现，替代初始虚拟列表建议；全部已收到数据仍可搜索、换页，不引入宿主分页假设。

工具可以有多个 C# 项目/程序集，具体拆分以可复现构建为准，不用目录分层强制制造过多程序集。发布品不打包工程源码或宿主环境；独立发布清单记录工具版本、支持的协议版本及构建摘要。

## 3. 首版功能与现行接口映射

路径前缀均为 /api/v1。所有修改均通过受控 API；接口未支持的字段只读，不提供绕过约束的“保存任意 JSON”。

| 区域 | 首版交付 | 现行接口/约束 |
| --- | --- | --- |
| 连接与概览 | 地址、账号登录、连接状态、房间名称/状态、协议、容量与运行概要 | GET capabilities/contracts/me/view/admin；POST login/logout；WS connect |
| 配置 | 列表/搜索/详情、新增、更新、删除及引用提示 | admin.configurations；configuration.put/remove。新内容须使用新配置修订；被任何实例引用时禁止删除；更新默认值不会迁移既有实例 |
| 规则 | 规则工件及源码/JSON 数据查看、修订对比、完整文件组暂存与激活 | admin/artifacts/{revision}、rule.stage/activate；回退为显式激活旧修订，不删除工件、不自动迁移旧流程 |
| 实例 | 活跃实例搜索、原始数值/标签/引用查看；按配置创建；编辑现有支持字段；归档 | view、entity.create/update/patch/archive；可编辑名称、数值、标签、owner、visibility、rules；其他字段只读。归档不是硬删除，仍有引用则拒绝 |
| 关系与进度 | 关系查看/新增/删除；进度查看与按键设置 | relation.set/remove、progress.set；不承诺关系原地修改、进度删除或多个命令组成原子事务 |
| 成员与房间 | 查看成员、调整现有成员角色/启用状态、暂停/恢复/归档房间 | admin、member.update、room.status；遵守最后一个 KP 保护；不提供账号创建/密码管理 |
| 流程 | 详情、等待、错误查看；有权限时响应布尔待办、取消、重试 | view/admin、flow.respond/cancel/retry；重试是新的阶段尝试，可能重新掷骰，不是命令重发 |
| 素材 | 资源表、授权上传/下载、实体挂接和无引用登记移除 | admin.assets、POST/GET assets、asset.attach/remove；不提供存储文件浏览或直接清理磁盘 |
| 观察 | 连接期间的状态差异、关注列表、最近操作审计 | WS 授权快照 + 周期 GET admin；观察差异与 admin.audit 独立显示 |
| 备份 | 创建房间备份、显示宿主返回的 backupId | POST backup；仅创建，非下载导出，不包含账号库，不自动打开宿主文件目录 |

普通 view/query 只包含授权活跃实例，无法完整浏览已归档实例；query 当前按相等条件过滤且最多返回 1000 项，不是分页 API。首版利用已收到的完整授权快照做本地搜索/排序/分段列表；不得把 1000 项查询结果显示成完整库。完整快照仍受宿主 2 MiB 限制，超限须明确报错，不显示为“空房间”。

不提供原始数据库/文件编辑器，不复刻完整游戏面板。聊天正文管理与游戏专用动作面板不列入本次必交；关注 chatChannels 只能观察频道元信息变化，不能宣称能跟踪每条消息的内容变更。

## 4. 模块职责

| 模块 | 职责 |
| --- | --- |
| UI | 五个工作区：配置与规则、房间数据、变化观察、关注列表、备份与运行状态；左列表、右详情/表单、底部回执。可编辑字段与只读原始结构同时可查 |
| Application | 登录/选中对象/编辑草稿/提交/刷新/退出等用例，不把 UI 控件当权威数据源 |
| Protocol | 固定 API 映射、认证、请求封套、重试判定、错误翻译、协议能力检查；可替换连接实现 |
| Observation | WS 分片装配、按来源维护基线、字段差异、观察缺口与关注条件 |
| LocalSettings | 默认连接配置、关注定义和最小命令查询记录（列宽/筛选暂不持久化）；不保存房间权威状态 |

页面展示来源时间与是否过期。原始 JSON 供查看/复制与排错，修改使用白名单表单或已知操作的参数编辑器；未知模型字段保留原值并显示只读，不因 GUI 不认识而删除。规则激活、实例归档、成员停用等操作显示具体对象和影响后确认；普通操作不反复弹确认框。

## 5. 认证与同步

原生 HTTP/WS 使用相同会话 Cookie；Origin 使用所连接宿主的规范来源，例如 http://127.0.0.1:8765，Host 由 URL 生成，写请求带 X-CSRF-Token。localhost 与 127.0.0.1 不混用。首版只允许回环地址，禁止自动将带凭据请求重定向到另一来源；不修改宿主 CORS/Origin 规则。

登录后检查 capabilities.protocolVersion 和 contracts，取得完整 view 并确认 KP 权限，再启动 WS 与单个 admin 轮询任务。默认 admin 轮询间隔 2 秒，手动刷新和管理成功后追加一次刷新；失败退避且不并发叠积请求。各数据源分别记录获取时间，view 与 admin 不构成一份跨接口原子快照。

WS 按 begin/part/end 装配，校验 ID、分片索引/数量、重复分片、大小与完成条件，只在完整时替换旧视图。不完整、超限或协议错误时丢弃并重连。连接断开即禁用写入；退避重连后重新取得权限与基线。未登录、权限改变、账号切换、宿主 authorityEpoch 改变时清空敏感缓存与旧草稿，不将旧数据解释成删除事件。

已读缓存的 KP 降权不能只依赖 admin 返回 403：每次新投影均检查 role/authorizationEpoch；发现失去 KP 立即清理管理数据、观察前后值并退出管理会话。后台任务附带会话代号，迟到响应不得进入新会话。

## 6. 写命令与冲突

命令封套遵循现有协议，携带 commandId、authorityEpoch，以及适用的 runId、catalogRevision、rulesetRevision、expectedViews。每次用户确认的业务提交生成一次 commandId；响应丢失时保持原封套，先查同账号回执，不换 ID 自动重做。HTTP 成功还须检查业务 status 是否 committed/rejected/pending。

实体编辑从编辑开始时保存 viewToken，提交时显式填写 expectedViews，禁止通过字符串搜索猜测目标对象，禁止临提交换成最新 token 掩盖过期草稿。VERSION_CONFLICT 时展示基线、当前值和拟修改值，由用户重新确认；一次表单涉及多个命令时逐条显示结果，失败不声称全部回滚。

配置、关系、成员、进度等操作并无统一的服务端 expectedRevision。提交前重读并比较可发现部分冲突，但不能消除检查与写入之间的竞争。首版对此标注“无原子版本保护”，建议同一房间单个管理写入者；不得承诺全面防覆盖。需要强并发保护时登记宿主扩展，不能私自给现有契约添加参数。

备份/素材上传等非 commandId 接口单独处理：响应超时显示“结果未知”，不自动重试，不假定未执行。关闭工具前提示仍有结果不明的写入；只保存用于下次查询的最小元信息（连接配置 ID、账号 ID、房间/场次标识、commandId、操作名），不持久保存完整封套、密码、Cookie、CSRF 或正文。重新打开后先认证与核对目标，再查询；无法恢复原封套时不自动重发。

查询/刷新成功后以宿主结果更新列表，不用 GUI 本地计算代替规则或写入校验。显示公开错误码及可执行处理方式，不把权限错误当网络重试。

## 7. 数据变化观察

首版标签固定为“观察到的变化”，与“最近操作记录”分开。WS 可能合并修改；HP 在两次采样间 10→5→8，工具可能只观察到 10→8，甚至 10→5→10 无差异。admin 轮询也有同样限制。admin.audit 仅最近 100 条且无统一字段前后值，不据此伪造完整事件链或操作者关联。

观察记录包含：
- observationId、观察段 sessionId、来源 view/admin、接收时间（本机时间）；
- 对象类别、对象 ID、字段路径、前值/后值、来源修订（若有）；
- 类型为新增/值变化/不再可见，以及关联关注项。

只有宿主记录明确提供命令/操作者时才显示对应关联；不凭相近时间猜测。字段路径采用可转义的路径表示，区分缺字段与 null；排除 viewToken 等传输字段，数组默认整体比较。对象退出授权视图标为“不再可见”，不能自动判成删除或归档。

第一份完整样本只建立基线。断线重连、宿主重启、身份/权限或房间切换新建观察段，标记时间缺口并重新建立基线，不把重连快照差异伪装成逐条过程。缺失的中间修改无法由首版补齐。

关注定义：连接配置 ID、roomId/runId、对象类别/ID、字段路径（或整个对象）、是否启用。公开房间 ID demo 不是跨宿主唯一标识；不得仅按它合并关注与历史。默认只提供值变化提示，可后续加阈值条件；首版不自动执行规则、修改数据或外发通知。

默认保留内存观察记录 2000 条，达到上限按最旧记录淘汰并显示计数；最多关注 100 项。只持久化关注定义，不持久化采样值。退出账号或撤权后清空值缓存。列表有界呈现、差异计算置于后台，UI 接收有界批量更新，过载时明确显示观察缺口。

## 8. 存档与后续接口边界

首版创建的是宿主侧房间备份。GUI 收到 backupId 后显示已创建，并说明不含身份库；返回 ID 不等于已下载到工具所在目录。不提供备份枚举、删除、恢复、热切换、编辑旧文件代或直接打开宿主存档路径。

后续分两个独立工作包，不作为首版发布门槛：
1. 完整变更历史：宿主在事务内记录顺序号、对象与字段前后值、命令/操作者、时间和作用域；授权分页、过滤、保留范围、游标失效与断线补查必须一起定义。新记录从启用时开始，不倒推已有快照为完整历史；不能复用首版观察记录冒充权威事件。
2. 存档管理：宿主提供备份列表/元信息、校验与受控导出/删除；恢复需明确停止写入、活动流程、身份绑定、恢复目标发布、会话失效和失败回退流程。停服后无法调用房间服务本身，需要独立生命周期入口或由操作者离线恢复，不能仅在 GUI 放一个恢复按钮就认为问题解决。

这些能力应作为稳定管理契约公开，GUI 仍不直接读写存储。未来可分别替换观察源与备份接口，无需重写编辑和关注 UI。

## 9. 验收与后续工作

首版退出条件由 [施工计划](../plans/room-manager-construction-plan.md) 统一维护：可复制 exe 独立连接、现有管理操作闭环、实体冲突保护、观察语义正确、断线/撤权清理、真实 GUI 操作可验收。

已知限制：单房间本机协议、全量快照大小、admin 轮询非原子、非实体操作缺统一 CAS、无完整历史、无在线恢复。不能通过放宽宿主校验、扫描存档文件或假造 UI 成功绕过限制。

R0—R6 首版已实现并进行本机验收，具体通过项、性能、原生窗口证据与验证限制见[验收报告](../../tools/room-manager/legacy/winforms/docs/acceptance.md)。当前不把多显示器混合 DPI、长期无人值守压力或所有网络故障组合视为已认证范围。后续 H1/H2、S1/S2 仍需接口设计与独立施工；不得因首版交付而写成现有能力。
