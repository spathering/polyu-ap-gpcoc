## 1. 问题与目标

2026-10-29 用户反馈：首轮 Lua 样例结构、格式、参数和 return 负担偏高。目标是普通作者/Agent 用短调用表达常见业务意图，少写重复注册、输入 schema、效果表及流程映射，同时保留权限、原子性、预览、版本和恢复能力。

Lua 语言选择不变。“一行”针对单项常见操作，不要求把复杂流程挤成一行，也不能把必要信息转移到更多手工配置中。

## 2. 已确认方向与职责

用户已同意按“简洁宿主 API＋效果收集＋少量稳定阶段”推进，并将 r 的定义及作者 API、执行上下文、规则包与通用内核的分层整合到[主方案第 3 节](../lua-authoring-facade.md#3-lua-宿主-api-与分层职责)。参数默认、错误、提交及等待语义均在该方案维护，本 Issue 不重复定义接口。

业务算法由规则包承担，内核强制执行身份、引用、数量守恒和提交约束。当前原型仍包含示例默认算法，完整规则包绑定待实现。

## 4. 关闭条件

- [ ] 常见动作一条清楚调用即可表达，无需效果列表和复杂 return；总制作文件与维护信息量确实减少。
- [ ] 默认对象、参数、权限、结果与错误、提交边界都有明确语义，用户/Agent 能独立完成规则和流程修改。
- [ ] 权限、不变量、预览、原子性和去重通过真实宿主验证；持久等待、重复回应、超时竞争和重启恢复通过故障用例。
- [ ] 动态发布与便捷函数版本不改变已开始流程；旧协议迁移有替代关系与验证。
