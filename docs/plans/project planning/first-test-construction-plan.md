## 1. 目标、范围与当前起点

按[工程设计](first-test-engineering-design.md)完成一份可重复启动、真实本机多身份联机、支持 Lua 自定义及跨日恢复的首测制品。以一个长期房间、一个 KP、两个玩家、两条业务用例为主线：

1. 准备人物/背包/物品 → 玩家查询并整叠或部分转移 → 其他获准身份看到同一权威结果。
2. 玩家检定 → 失败后等待 KP → 宿主中断重启 → KP 回应 → 校验并执行后果；等待中发布新规则，旧流程保持原版本。

另用只读组合攻击值、个人事件记录、限时选择及素材引用验证已确认的数据设计。原首测使用自制规则验证宿主；聊天室后端已在追加任务落地。完整 COC 归规则包，地图战斗暂不作为必要能力；LAN/公网发布或 P2P 未纳入实现。产品 UI 不在本阶段验收范围，最小操作台仅用于验证契约与管理闭环。

当前已有 A0/A1 同步内存 Lua 原型、三份运行样例、裁定纸面稿及此前记录的 56 项断言结果。该数字不是本次新跑的结果，不能作为文件持久化/联机/故障恢复的验证。现有设计已经足以启动 E0/E1，依赖精确版本与具体机器契约在这两关形成；该段描述施工前基线；当前已创建后端、SDK 和文件存档实现，实际结果见本页实施状态。

2026-10-30 用户确认首测使用独立的文件数据管理模块。以下工序已替换此前 SQLite 方案；数据库选型、安装及迁移到数据库不再是首测前置任务。

## 2. 总体顺序与工作规则

```mermaid
flowchart LR
    E0[E0 运行时与工程骨架] --> E1[E1 契约与固定样例]
    E1 --> E2[E2 持久内核与固定规则]
    E2 --> E3[E3 本机真实联机]
    E3 --> E4[E4 动态 Lua 与持久流程]
    E4 --> E5[E5 管理 / 素材 / 备份]
    E5 --> E6[E6 故障验收与交付]
```

关键顺序为“契约 → 持久状态 → 真实多身份连接 → 可恢复自定义 → 管理交付”。每关先验证纵向最小用例，再补该关必要的失败路径。未通过的退出条件继续修复，不能靠增加后续模块掩盖基础问题。

- 每次开工读取 hierarchy 并以独立 ID 登记实际读写范围；拟建目录不等于已获永久占用。范围扩大前补登记，结束释放。
- 通过端口和 fixtures 划分任务边界，不默认开启并行 Agent；以后多人协作仍遵循读写占用互斥。
- 当前 A1 原型保持可运行，正式模块按分层重建并复用行为测试/样例，不把实验 `host.lua` 原地扩成所有职责的单文件。
- 每项交付更新实际工程说明、运行步骤和 hierarchy；计划只更新真实进度。待实施能力不写成当前工程事实。
- 每关附“变更范围、验证命令、环境、结果、剩余问题”。依赖锁、接口变更和故障证据进入对应有效来源，不以聊天回忆替代。
- 本计划不设未经实测的工期承诺。E0 后按安装与探针耗时估算 E1/E2，E2 后以持久内核联调成本滚动安排剩余工作；正确性与范围先固定。

## 3. 分阶段工作包

### E0：运行时探针与工程骨架

目标：证明推荐技术基线能在目标 Windows 环境使用，确认代码/运行数据/测试数据的隔离和后续施工入口。

| ID | 工作与拟建范围 | 必须留下的产物/证据 |
| --- | --- | --- |
| E0-01 | `engineering/backend/` 项目骨架、虚拟环境及运行/开发依赖锁 | Python、Lua、存档格式与依赖精确版本/摘要/许可证；无系统 Lua、无本机编译器安装结果 |
| E0-02 | `adapters/lua_worker/` 小探针，导入现有可信样例 | 明确加载 `lupa.lua54`；中文文本、nil/空表/数字边界；禁止 Python 属性/builtin/eval 与脚本文件/网络能力的探针 |
| E0-03 | 独立执行器探针，不接真实游戏存档 | Windows spawn、正常退出、死循环硬终止、内存超限、迟到结果丢弃；父服务保持可响应，无残留工作进程 |
| E0-04 | 最小 FastAPI/WS、文件快照提交、文件锁探针 | 真实回环 WS 往返；写入/刷新/发布中断、磁盘满与损坏检测；第二宿主争用房间失败；依赖装好后断开 WAN 仍可冷启动 |
| E0-05 | `scripts/`、数据目录配置与工程说明 | 固定安装/检查/启动入口，无自动重载；运行数据与源码分开，实际新增路径登记 hierarchy |

退出条件：所有探针可重复执行；精确锁定依赖；决定执行器进程生命周期及实际限额。Python/Lupa 组合或子进程取消不成立时先修订工程设计，不带着不可终止的执行器进入 E2。首测基线在计划中标记验证结果，已实际验证的环境/命令再进入当前工程文档。

### E1：契约、ID 与固定数据定稿

依赖 E0。目标：后端、SDK、Lua 宿主和 Agent 共用可以检查的契约，不再靠各自理解字段。

| ID | 工作与拟建范围 | 交付物 |
| --- | --- | --- |
| E1-01 | `engineering/contracts/` 中的通用模型 schema | Account/Member/Room/Run、Entity/Relation/Container、配置与规则引用、个人记录、素材元数据；公共封套和保护字段 |
| E1-02 | 请求/回执/错误/投影/目录 schema | roomId/runId/authSessionId 等唯一含义；action.invoke、CRUD、管理、回应的独立输入；同一源生成/复用 HTTP 与 WS 校验 |
| E1-03 | `engineering/rulepacks/demo/` 的类型、配置、固定规则清单 | 属性单位/范围、固定 percent-check/伤害/容量算法、组合值只读算法；算法从通用内核分离 |
| E1-04 | 正反 fixtures、动作描述生成验证 | 两把不同耐久的同配置物品；技能实例及归属；部分转移；不同来源状态；玩家/角色个人记录；KP/玩家的不同投影 |
| E1-05 | Lua 边界与短输入声明 | 三个既有简单规则的等价输入/输出；不让作者手写完整网络 schema 或效果协议；确定最小语法后回写编写方案 |

退出条件：有效 fixtures 通过、非法形状及越界数字被拒绝；有限权限投影不含密码或隐藏字段；相同动作声明生成后端验证与表单/Agent 描述，例子不靠前端猜参数。来源正文和字段表同步，首测命令不再混用 campaignId/sessionId。

### E2：持久内核、账号与固定规则纵向链路

依赖 E1。此关先用 CLI/无界面驱动，不依赖浏览器页面完成业务。

| ID | 工作与拟建范围 | 交付物 |
| --- | --- | --- |
| E2-01 | 独立 `engineering/data-management/`、FileDataStore、RoomRepository/IdentityStore | 分离账号与房间文件存档；版本快照/索引/提交/查询/恢复接口及格式迁移；不支持版本进入维护模式 |
| E2-02 | 本地账号、成员与最小管理 CLI | 创建账号、设置密码、创建/打开房间、配置 KP/player 与角色控制权；CLI 共用应用层校验 |
| E2-03 | 实体/关系/容器与暂存视图 | 配置初值复制、注册/引用分离、受控增改归档、实际读集及集合版本、数量守恒/唯一持有/循环检查 |
| E2-04 | 固定规则包的 RuleExecutor 绑定 | check/damage/transfer；只读组合值与 action 模式隔离；后续调用读到前序拟结果；无复杂效果 return |
| E2-05 | 命令尝试、随机记录、原子回执/审计/Outbox | T1/随机记录/T2 边界；同 ID 摘要校验、拒绝持久化、旧回执权限过滤 |
| E2-06 | 核心持久化及早期故障测试 | 提交前/后杀进程，恢复同命令不重复扣血/拆分；非法第二次操作整段回滚；双身份竞争同一数量 |

退出条件：重开房间后状态/回执/个人记录一致；检定、伤害、整叠与部分转移走同一管线；权限与模型不变量不能通过普通 patch 绕过；重开文件存档得到同一权威结果。未提交骰面不提前广播，已记录随机调用重试不能更换骰面。这里的固定工件锁只是 E4 动态发布的基础，不宣称完成热加载。

### E3：可替换联机模块与本机多身份测试台

依赖 E2。目标：真实连接贯通已验证内核，页面不包含第二套规则计算。

| ID | 工作与拟建范围 | 交付物 |
| --- | --- | --- |
| E3-01 | HTTP/WS adapter + ApplicationGateway | localhost 同源入口、版本/限额、身份绑定、Cookie/Origin/CSRF/Host 检查；无客户端自报 principal |
| E3-02 | SDK TransportPort 与命令追踪 | commandId 重用、unknown 查询回执、断线禁止新写入、目录获取、取消/错误映射 |
| E3-03 | 授权投影与订阅 | 同边界快照和后续缓冲、原子 batch、字段移除/reset、慢客户端限额；重连统一快照 |
| E3-04 | `engineering/test-console/` | 登录、房间/角色、数值/背包、动作输入、回执、连接状态、管理信息；不实现正式复杂面板 |
| E3-05 | adapter 一致性与真实浏览器验证 | 内存适配器与 HTTP/WS 调用相同请求序列；三个隔离身份通过真实回环连接，结果及过滤一致 |

退出条件：KP 和两位玩家同时查询/操作同一房间；两位玩家无法互相取得隐藏字段或 KP 权限；同条命令跨重连返回原结果，实时更新先于回执也不会重复应用。快照发送中继续写入不丢变更，撤权后旧缓存移除。记录 3/8 连接的队列、时延、内存、快照字节基线，不预设通过即支持相同规模公网部署。

E3 完成可交付“本机联网切片”，但首测整体仍待 E4—E6。回环验收只覆盖同电脑的真实网络栈，不覆盖 LAN、防火墙、手机或 NAT。

### E4：动态规则与持久流程贯通

依赖 E3。目标：落实运行中新增规则和等待后恢复，并保持作者接口简洁。

| ID | 工作与拟建范围 | 交付物 |
| --- | --- | --- |
| E4-01 | 不可变 RuleArtifact/RulesetLock、加载/发布管理 | 手动导入与整组校验、数据文件快照、依赖环/深度、预览、差异与原子激活；失败仍用旧锁 |
| E4-02 | 配置行为入口与动作目录刷新 | 事件→主流程；对象规则槽仅引用；公开调用按当前目录入口授权，不能绕行任意内部规则 |
| E4-03 | Flow/Step/Wait、调度恢复 | 稳定节点 ID、阶段原子提交、待办、回应 CAS、后续权限复查、needs_attention/取消；无协程栈存档 |
| E4-04 | 检定—裁定—后果与限时选择 | 同题短脚本/模板；回应与超时只能一方生效；重启继续原期限和分支 |
| E4-05 | 热更新与旧版本故障测试 | 等待中更新/删除原文件、升级便捷库、重启、旧 schema 回应；旧流程保持原锁，新行动使用新锁 |

退出条件：不重启宿主/重建前端即可新增动作并在目录出现；旧流程可以从保存源码/数据重建；规则成环或预览失败不会半发布。计算规则不能掷骰/改值；KP 裁定不提权，等待后对象变化须复查。作者常见操作仍为一条业务调用；持久阶段结构的复杂度在原 Lua 方案集中修订，不能再增加一套互不兼容的示例协议。

### E5：管理、素材与备份恢复闭环

| ID | 工作与拟建范围 | 交付物 |

| E5-01 | 房间/数据管理接口与页面/CLI | 暂停、继续、归档、成员撤权、配置/实例检查、个人记录、引用阻止删除、审计检索、卡住流程定位 |
| E5-02 | AssetStore 本地实现 | 暂存/摘要校验/ready 登记/授权读取/引用检查；业务只存 assetId，孤立暂存文件延迟回收 |
| E5-03 | 一致备份与独立目录恢复 | 暂停写入/发布/回收，固定提交代的文件导出接口、规则工件及素材清单；校验后恢复；账号绑定策略明确 |
| E5-04 | 运维与扩展文档 | 开发启动、数据路径、停止行为、规则导入/激活/回退、备份/恢复、版本/限额、错误排查、联机/资源端口说明 |

退出条件：有引用对象不会被隐式级联销毁；秘密资源不能凭摘要或文件名越权读取；完整房间可在新目录恢复，包含配置/实例/规则锁、流程、回执、共享与个人事件记录及素材。房间备份与完整账号存档备份分清，跨宿主不按昵称自动继承权限。恢复失败保留原存档，不覆盖运行房间。

| E6-02 | 空数据目录与干净环境复现 | 安装→建账号/房间→多身份游玩→热更新→中断→恢复→备份恢复；运行时不依赖 WAN |

## 4. 必须覆盖的验收矩阵

| 编号 | 场景/注入方式 | 观察与通过条件 | 最早关口 |
| --- | --- | --- | --- |
| V01 | 两把不同耐久的同配置物品；名称相同/改名 | 实例不同，配置条件均可命中；修改不串对象，名称不作关联键 | E1/E2 |
| V02 | 整叠转移、3 件转 1 件、第二次拟操作失败 | 整叠保留 ID；部分新 ID；数量守恒；失败无残余效果 | E2 |
| V03 | 非法持有、包含循环、跨房间引用、归档被引用目标 | 明确拒绝，不产生悬空关系或隐式销毁 | E2 |
| V04 | 同 commandId 重发/改参数；两位玩家争同一数量 | 同内容同结果；异内容冲突；仅合法动作提交，不透支 | E2/E3 |
| V05 | T1 前后、骰面落盘后、T2 前后分别强制终止宿主 | 未提交无业务效果；已提交不重做；骰面不更换；恢复可解释 | E2/E6 |
| V06 | 提交成功丢 HTTP 回执、更新先到、广播前崩溃 | 客户端 unknown 查询原回执；不再扣减/拆分；重连得权威快照 | E3/E6 |
| V07 | 伪造账号/角色/权限，读取他人字段、旧回执或素材 | 不提权、不泄漏密码/秘密内容/存在性；操作和查询统一授权 | E3/E5 |
| V08 | 快照中持续写入、撤权、慢连接溢出/断线 | 无缺口或明确 reset；旧秘密缓存清除；其他连接继续工作 | E3 |
| V09 | 多次刷新组合攻击值；计算规则调用 action/随机 | 数值正确且无状态/骰面变化；非法模式交叉被拒绝 | E2/E4 |
| V10 | 非法新规则、依赖成环、超深调用、运行死循环 | 无半发布；旧规则可用；工作进程可终止，父服务继续响应 | E0/E4 |
| V11 | 等待中修改/删除 Lua 及数据文件，发布新修订并重启 | 原流程/旧输入契约/骰面保持；新行动用新锁；缺件不静默替换 | E4 |
| V12 | 阶段完成后/待办建立前故障、重复回应、回应与超时竞争 | 不重检定；同 waitId；只走一个分支；重启不重设期限 | E4/E6 |
| V13 | 等待中转走目标/耗尽资源/撤销发起者权限；KP 同意 | 后果按当前状态复查，可明确失败；批准不提权、不撤销既有阶段 | E4 |
| V14 | 保存后次日重开，原身份登录 | 一个共享世界；玩家和角色各自的解锁/触发/待办恢复，旧缓存不能覆盖 | E5/E6 |
| V15 | 备份中失败、资源缺失/摘要错、迁移不支持、新目录恢复 | 不标记坏备份成功；原存档保留；成功恢复状态/工件/资源一致 | E5/E6 |
| V16 | 不同 TransportPort 处理同一固定输入/随机 fixture | 相同持久结果、错误、授权视图与回执；内核不导入联网框架 | E3/E6 |
