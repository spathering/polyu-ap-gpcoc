## 1. 当前实现

本包 0.2.0 在现有首测宿主上实现确定性行动自动化和必要事项人工裁决。配置包含23地点、22道具、12线索、7谜题、4预设角色、4个NPC、7事件和5结局；13个Lua文件导入宿主，数据与规则固定到修订。启动适配、自动化服务、界面、测试和运行输出均在本包，没有修改 engineering/。

界面采用桌面单标签主导航与二级分区。PL 在场景页完成可达导航、探索、机关与领取，小地图为场景内折叠小窗，按每个PL的实际探索记录只显示已探索房间与一跳可见周边；其他分页提供线索、背包和记录；KP 总览展示必要裁决与自动日志，管理分五区。背包、聊天及独立 KP 队列可拖动、缩放、折叠。行动卡、历史计划、骰子与备份显示人可读文字，配置文件导出仍可使用 JSON。

常规移动、探索、侦察、休息、安抚、等待、标准谜题、条件领取、装备与消耗自动调用宿主规则。转交由接收者确认，玩家攻击由防守方确认防御后自动结算。KP 可通过顶部“下一轮”主动推进，自动处理关闭时也可用；请求可恢复且不重复推进。完整行为表、导航和逻辑图见[自动行动与界面](automation-and-ui.md)。自定义方法、语义差异、NPC 决策和未定义剧情进入必要裁决。

## 2. 启动与更新

需要已安装的 engineering/.venv 环境。直接双击包根目录五个[原生账号入口](../tools/README.md)，或在项目根目录执行：

```powershell
& '.\rulepacks\mini-detective-pack\start.ps1'
```

默认本机地址 http://127.0.0.1:8888。首次网页设置8—128位初始密码，五账号共用本次初始密码；自动建立规则、时钟、四角色及初始道具。后续不重建存档。不同账号入口使用隔离 Cookie，入口名称不是授权身份，仍需登录。

原生入口以隐藏监督进程持有服务，关闭浏览器不停止服务。KP 可在“日志与设置”或“主持管理 → 开局与存档”停止；PS1 前台启动也可 Ctrl+C。服务固定回环，尚无 LAN／公网访问。

旧版本升级需要重启适配器。KP 登录后直接使用顶部“自动处理”总开关：默认关闭，关闭时行动交 KP；开启时直接结算。首次开启会为兼容旧存档补齐缺失自动条件，保留在线场景编辑和角色资源；开关状态随存档持久保存。缺失预设可另点“建立缺失的4个预设角色”，已有角色不会改成预设或重复补发初始物。

自动化使用独立 KP 会话；人类 KP 退出页面不影响它。Windows 会话 Cookie 用 DPAPI 加密，密码不持久保存；到期需 KP 重新登录。默认 runtime/room/ 保存宿主数据，runtime/room-automation/ 保存队列、日志、获取记录及逐步命令凭据。停服迁移时必须一起复制。网页主机备份不包含后一个目录，在线恢复仍未接入。

## 3. 接口与配置

同源适配代理既有 /api/v1，并校验 Host、Origin、Cookie 和 CSRF。/package/action 仅接受固定游戏行动，GET /package/automation 按登录身份返回状态，POST 同一路径只允许 KP 修改总开关。/package/bundle.json 只给 KP；公开元信息和玩家投影不含完整场景或谜底，素材静态入口也不公开全量绑定 manifest。

状态接口按角色返回当前场景、真实相邻出口、可用行动和限制原因，读取活动场景修订。自动化序列化处理行动，创建实体、关系和确认仍使用多个既有 API；每步先保存原命令，再发送、查询回执和缓存结果。重复同一行动编号返回原结果，改变原内容会被拒绝。响应未明时必须恢复原行动，不生成新编号重复执行。

md.character/md.world/md.item/md.bag 均使用通用 actor 模型。md.item 是本包卡片实例，不是工程原生 item.quantity。角色同时保留 hpMax 和工程 maxHp，建卡同步二者。配置默认字段变更需增加配置修订；新增 automation 为场景数据，不改既有角色默认数值。

KP 可按地点、道具、线索、谜题、人物、事件、结局编辑字段并发布活动修订。自动处理读取活动工件的 automation 段；题面文字编辑不等于修改机器判定。配置作者应同步维护条件与文案。导入 Lua 必须可信；配置导出含谜底，仅给作者和 KP。

## 4. 验证与边界

真实宿主验证覆盖自动行动权限、私密投影、请求重放、提交后响应丢失恢复、条件谜题、资源和物品流转；浏览器验证覆盖分区导航、私密地图、建卡、独立队列及原生五账号入口。准确数量及最近机器证据见[验收索引](../tests/README.md)。这不代替四人完整跑团和平衡性验证。

仍需人工的范围：多队速度调度、NPC 自主决定、特殊方法和未配置物品用途、逃跑追击、倒地救援及部分叙事事件。人工管理 API 与旧 Lua 仍保留，自动入口的入口、时钟和终局校验不是工程全局冻结能力。多步骤操作可恢复但不提供跨 API 原子事务；在线备份恢复与组合管理接口边界继续见 [ISSUE-004](../../../docs/plans/Issues/issue-004-mini-pack-management.md)。
