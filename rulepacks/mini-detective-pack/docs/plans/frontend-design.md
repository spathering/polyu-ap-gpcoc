## 1. 目标与范围

基于新增`raw/UI/`的三张截图，为`reconstruction-0.1`规划一套人工主持的调查桌面。KP指主持人，PL指操纵角色的玩家。目标是在一个桌面完成阅读反馈、报备行动、判定、领取与制卡、交换线索，同时让KP处理多人私密裁定。**桌面界面及确定性行动自动化已实现；以下五项方向已由用户于2026-11-02确认，其余未落地布局仍为提案。**

实施更新（2026-11-02）：本文件保留设计基线，现有0.2.0已实现常规行动自动化、分区导航、接收者转交确认及防守方选择。当前流程和Mermaid见[自动行动与界面](../automation-and-ui.md)。停靠、在线恢复、自动多队调度及4人完整跑团仍待实施或验证；原计划描述不代替当前能力说明。

| 已确认决定 | 本版执行口径 |
| --- | --- |
| 网络素材暂作占位 | 已下载20份占位资源，按资产ID绑定，替换美术不改游戏规则；来源与许可见素材索引 |
| 手绘卡允许文字替代 | 线索卡和道具卡都可纯文字完成，图像可选，不因缺少绘图或上传阻塞游戏 |
| 暂不考虑手机 | 仅设计桌面鼠标／键盘布局，验收基准1280×720与1440×900；移除手机导航与小屏适配任务 |
| KP队列独立窗口 | 使用页内独立浮窗W-KP-QUEUE，可移动、缩放、折叠和停靠；切页后保留 |
| 所有人仅从前端操作 | 每人一个浏览器标签页，内部功能分页＋可折叠浮窗；房间准备、KP裁定、管理、存读档与PL行动均有前端入口 |

“仅从前端操作”限定用户操作入口，服务端仍负责身份、秘密投影与权威结算。既不要求用户编辑JSON、输入CLI、调用API或用外部群聊补足流程，也不把全量秘密数据改为所有客户端持有。

截图是用户指定的界面参考，未附可运行源码或交互录像。只根据可见状态提取布局，不推定截图背后的服务、权限、存档和按键已经可复用。当前按本地项目实现，未发布外部托管。

## 3. 视觉与布局提案

延续参考的暗底、金色标题、圆角面板和大尺寸选项；用本包原图已有的旧纸、档案和海岛意象表达调查氛围。以下是建议设计值，不是从截图精确取色：背景`#17170F`、面板`#272313`、主操作`#79651E`、标题`#E5D579`、正文`#EFE8CB`、次要说明`#BDB59A`。正文衬底保持纯色，纸纹只放边缘；不让背景图穿过长段正文。

桌面宽屏主区约60%阅读／地图、40%操作，人物状态用紧凑侧条或顶部摘要；KP同样保留宽阅读区，但可切到宽地图和队列。建议正文17—18px、行距约1.6；主按钮文字允许多行，卡面不截断“待确认”“余量”等关键状态。聚焦、选中、待提交、执行中与失败均同时有文字／图标，不靠颜色区分。

| 桌面视口 | 排布 | 常驻信息 |
| --- | --- | --- |
| 1440×900及以上 | 顶栏＋内部页签＋双栏主区；浮窗可在侧面停靠 | 游戏日／轮、本人资源、当前频道、当前待办 |
| 1280×720 | 收紧边距；队列可停靠或折叠；窗口内容内部滚动 | 保留主操作与待办入口，不能被浮窗永久遮住 |
| 小于桌面基准 | 允许主区滚动并提示调整视口；可恢复默认布局 | 暂不作手机、触摸或底部导航验收 |

长日志单独滚动，出现新消息时若正在读旧段落只显示“新消息”按钮，不强制跳底；当前动作区不跟随日志滚走。角色背景以页内浮窗查看，避免把大段说明塞入主操作区。关闭还原焦点；Esc关闭最上层可关闭对话框，B打开或聚焦背包，M切换地图，输入框聚焦时不触发快捷键。暂不设计手机交互。

## 4. 共用入口与建卡页

房间入口显示房名、包版本、主持人、时钟模式、本人身份、连接状态和“进入”。KP／PL身份由房间授权决定，不提供可自助提权的身份切换开关；无角色的PL先选卡或建卡。多角色控制不在首版范围内。

建卡页左侧：姓名、头像、六维加减与余下点数、预设四张卡、HP／体力／智力额度预览；右侧：才能候选、适用边界、初始物及说明。初始物按规则是一件经审核日常物，不设置截图的购物点数；选预设会完整替换尚未提交的草稿，已提交则先撤回。才能力5显示在独立栏，不能看成某六维免费+5。

底部按钮依次为“保存草稿”“提交KP审核”；通过后变为“准备好了”。未满足20点、单项越界、才能范围空、初始物不合法时显示具体字段错误。KP审核可以通过或退回理由，不能无提示改掉PL选择。场次开始锁定初始卡；后续变更走有记录的裁定。

## 5. PL主桌面

### 信息分区

| 区域／页面ID | 展示内容 | 主操作与边界 |
| --- | --- | --- |
| 顶栏 PL-DESK | 场次、游戏第几日／第几轮、当前地点、连接状态 | 地图、背包、卡册、队伍、聊天、规则、设置；离开仅断开界面，不默认为退出冒险或丢弃物品 |
| 左栏 PL-STORY | 公共公告＋本人授权的探索／遭遇回执，明确频道标签 | 阅读、按轮筛选、展开骰子细节；公开卡入口不携带原始私聊副本 |
| 右栏 PL-ACTION | 当前需要本人作出的决定；费用、剩余次数、后果预览 | 根据阶段显示计划、方法、掷骰、防御、领取或结局选择；每次提交有确认状态 |
| 计划 PL-PLAN | 每日8轮列表、已结算锁定区、未来草稿区、队员邀请 | 提交目的地与方法；未结算内容可按规则修订；组队不代替他人确认，不自动跟多数 |
| 地图 PL-MAP | 已授权地点和通路，本人位置，明确公开的队友位置 | 选地点看已知描述、可达路径和预计轮数，加入计划；点击不直接瞬移 |
| 背包 PL-BAG | HP、体力、智力额度、六维、状态、才能和4槽，当前装备武器 | 使用、转交、寄存、丢弃、制卡；待确认物占槽且不能用；资源名称不能简写成同一个“行动值” |
| 卡册 PL-CARDS | “我的原始回执”私有页签与“共享线索卡”页签 | 新写线索卡并选择受众；原始回执无一键转发，不以真假标签暗示其他玩家 |
| 队伍 PL-TEAM | 已同意协作的队员、计划邀请、可公开状态 | 接受／拒绝组队与转交，查看被共享的信息；不展示别人私密库存与完整计划 |
| 聊天 PL-CHAT | 公共频道、本人队伍频道、本人和KP的私聊 | 输入前常驻受众标识；切频道不沿用上个频道的未发附件；不提供任意读取他人私聊 |

角色资源始终写成“HP 9/9”“体力2/3”“智力额度3/3”“侦察已用1/2”；时间写“第1日·下午1”。预测到达耗时按当前可知路径显示，隐藏边不参与PL端路径算法。未获授权地点可完全省略；若KP明确公开“未知入口”，也只能显示该公开占位，不把真实节点名、库存数、NPC或谜底发给PL。

### 当前行动与异常状态

提交探索先预览体力成本和目标，0体力时明确标“强行行动，将抽疲劳”；逃跑体力不足则按钮禁用并给出原因。掷骰按钮只在收到对应请求后出现，不允许自由掷一个好结果再指定用途。战斗守方先锁定对抗／闪避，攻击结果之后才显示；装备不能在一次已锁定攻击途中切换。

发现道具不是自动入包。右栏列出本次可领取对象、份数及“领取／分给同地同意者／暂不领取”。满4槽时打开背包处理当前领取相关的转移、寄存或丢弃；不能用“事件中禁整理”把玩家卡死。其他未参与行动者可继续处理自己的待办。

错误状态明确区分：未轮到、KP待裁定、等待队员确认、库存已被领取、状态已更新需刷新、断线待同步、场次已结束。断线不清空草稿；重新连接先取回现有结果，再允许操作，不显示“重新掷骰”作为重试网络请求的替代。

## 6. KP工作台

KP不是PL界面额外加“下一轮”按钮：核心工作是安排多人行动、决定受众、核验结果与保留改判记录。

| 页面ID | 布局与信息 | 操作 |
| --- | --- | --- |
| KP-DESK 总览 | 顶栏游戏时钟／暂停；主区当前裁定与角色摘要，队列在独立页内窗W-KP-QUEUE | 从队列选择待办定位主区；按轮、队伍和类型筛选；不自动催促或公开计划 |
| W-KP-QUEUE 裁定队列 | 常驻独立浮窗，状态分为待处理、等待PL、可结算、已完成 | 点击打开KP-RULING对应对象；折叠仅收起窗口，不取消请求；数量标记持续更新 |
| KP-PLAN 计划与到达 | 8轮时间表、各队最慢速度、到达顺序、局部动作计数 | 锁定轮次前核对冲突、缺席和固定事件；邀请修改、确认覆盖，按规则结算 |
| KP-MAP 主持地图 | 全部23地点、条件边、已揭露对象、隐藏库存、NPC与触发器 | 选择玩家／队伍预览其可见范围，显式“揭露描述／揭露通路／发放线索”，不一次公开整张图 |
| KP-RULING 裁定 | 上方计划和已收费用；中间环境、目标、骰子、效果；底部受众和投送预览 | 发请求、确认规则结果、发核心信息或额外奖励；每次投送先看受众和仅向其发送的文本 |
| KP-LOOT 道具与制卡 | 实例来源、当前归属、剩余份数、产出额度、卡槽、待确认卡面 | 分配唯一物、审核／退回卡面、确认转移；不另造同名副本绕过库存 |
| KP-COMBAT 遭遇 | 先攻序列、攻击阶段、已锁防御、参战资源、HP及结算公式 | 控制NPC、发请求、结束战斗并执行一次战后抽取；仅明确操作才进入下一次攻击 |
| KP-EVENTS 公告与世界 | 固定事件E1—E7、开关、阵法／午夜策略与结局候选 | 预览公告覆盖范围；分清公告、占轮事件、附加遭遇；结局必须等玩家选择 |
| KP-LOG 日志与恢复 | 请求ID、版本、原骰、费用、发放、公开范围和改判链 | 暂停，检查冲突，追加带理由的补偿裁定；不直接擦掉旧结果 |

“结束本轮”前列出尚未完成的掷骰、待决定领取、结局选择和影响本轮的战斗；允许KP暂停处理或依据规则将缺席者设休息，不能一键丢弃玩家未处理物品。制卡可以跨轮待审核，但未确认卡不能使用；其领取归属及资源结算必须已完成。

“玩家视图预览”是KP内部的授权结果预览，不是把全量数据放进PL客户端后隐藏；KP不能因此代替该PL提交选择。公共投屏使用同标签页的脱敏展示分页，进入时收起KP秘密浮窗并只渲染公共投影，返回后恢复KP布局；首版不要求另开浏览器窗或标签页。

## 7. 界面与领域数据的对应

| 展示需求 | 既有草案对象 | 本次补充的计划字段／要求 |
| --- | --- | --- |
| 当前待办 | Session,Plan,Encounter | PendingDecision：id、kind、assigneeIds、allowedActions、causeId、status；等待条件明确，不作为新的规则权力 |
| 分人揭露地图 | LocationDefinition,EventLog | MapReveal：subjectIds、locationId或edgeKey、revealedFields、eventId；每个玩家独立记录，公开需显式目标 |
| 领取与制卡 | ItemInstance,TeamVisit | cardState区分pending／confirmed；实例归属先确定，审核只确认卡面，不再生成物品 |
| 私密叙事与公开卡 | EvidenceReceipt,PublishedCard | 私密原始回执与公开重写卡使用不同输入模型和受众；公开卡不透出clueId等秘密关联 |
| 地图联动行动 | Plan,LocationDefinition | 只按授权边计算路径；加入计划与执行分开，禁止单击地图自动扣款 |
| 网络恢复 | EventLog,ResourceLedger | 页面保留operationId／revision，结果未知先查询，重复点击不重复消费 |

这些字段同步到配置文档的界面适配段，尚不对应任何已验证API。地图与库存必须由服务端或受信任主持执行层按用户身份过滤；前端禁用按钮只是反馈，不能代替权限校验。能力不足时由KP在前端的反馈编辑器手工写脱敏文字并选择受众，不依赖站外工具；权限不能满足时应记录工程缺口，不能把秘密配置塞到PL页面绕行。

## 8. 分阶段计划与交付条件

| 阶段 | 工作与产物 | 依赖／完成条件 |
| --- | --- | --- |
| P0 文档与资源基线 | 本文、界面流程图、地图道具图及网络占位素材；五项决定入文档 | 交付为计划和本地资源；未代表界面已实现 |
| P1 静态界面样稿 | 桌面单标签分页、建卡、文字卡、PL桌面／背包、KP独立队列浮窗／裁定 | 使用占位资源和假数据；1280×720与1440×900核对长文本、窗口布局和恢复 |
| P2 单主持手动闭环 | 前端创建／载入房间与配置、角色审核、计划、反馈、制卡、地图揭露、存读档 | 游戏参与者全程不需要CLI／手改文件／外部聊天；核查工程入口，缺口提Issue，不隐含修改工程 |
| P3 多人同步与流程 | 多队到达、战斗、防御锁定、重连、原子领取、按轮推进 | 两名PL并行操作不泄密、不重扣，KP能逐项追踪 |
| P4 完整场景验收 | 2人／4人各走一条非战归航线，另验一次遭遇与午夜 | 游戏逻辑正确、界面不卡流程，材料按权利状态替换后再考虑发布 |

当前已有本机包与专项验收，P1—P4按本节开头的实施更新继续验收。关键验收包括：20点建卡与单项边界；才能不伪装属性加值；4槽满包仍能处理领取；纯文字能完成两类卡片；队伍邀请不代替本人选择；未知地图和假线索不泄漏后台真假；KP明确受众后才投送；PL不能自行推进轮次；断线返回原骰与原结果；切页、折叠或关闭浮窗不丢草稿或取消待办；KP队列跨内部分页保持；一次完整开局至结局不要求站外操作。

## 9. 待确认事项与默认选择

保留金色暗底方向，桌面单标签与分离KP／PL工作区；关闭多数自动跟随与强制倒数，时钟使用现规则的manual默认。地图先用节点逻辑图和地点列表，场景和道具用已下载类别图标、纸纹和文字占位；不用背景图伪造真实地图，不把剧透Mermaid直接嵌入玩家页。

待确认只保留：暗金配色的最终色值、后续正式美术方向、是否增加经明确授权的倒数功能。文字替代、桌面范围和独立队列已确认，不再作为待办问题。头像先用hood剪影占位；替换不影响角色数据。

## 10. 单标签页工作区与窗口管理

每个参与者只需一个浏览器标签页。内部“分页”切换主内容，不创建新标签；页内“独立窗口”是同一DOM工作区内的工具浮窗，不是OS窗口或`window.open`。房间入口／建卡属于前置分页，入桌后使用下面的功能区。

| 功能区 | PL主分页 | KP主分页 | 可同时保留的工具窗 |
| --- | --- | --- | --- |
| 场内叙事与行动 | 桌面：左叙事／右待办 | 裁定桌面：当前队伍、反馈、资源与受众 | 待办、角色、聊天；KP队列 |
| 每日行动 | 计划分页，8轮草稿与邀请 | 轮次分页，所有队伍、到达顺序与锁轮 | 聊天、KP队列 |
| 空间与信息揭露 | 已知地图分页 | 主持地图分页，地点／边／库存编辑与揭露 | 地点详情、角色、KP队列 |
| 证据与卡片 | 卡册分页：私有回执、共享卡、文字编辑器 | 档案分页：原始证据、投送记录、卡面审核 | 卡片详情、编辑卡草稿、聊天、KP队列 |
| 人物与道具 | 背包默认浮窗，可展开到主分页 | 角色与库存管理分页 | 四槽背包、物品详情、转交确认、KP队列 |
| 世界、事件与存档 | 仅开放本人结局和已授权记录 | 场景／事件分页，房间管理分页，日志／存档分页 | 事件预览、公共展示预览、KP队列 |

所有人仅在前端操作的功能覆盖：KP房间页可选已装包或用文件选择器导入包、建房、邀请和分配角色；场景页可用表单检查和编辑本场地点、道具、谜题、NPC与事件；规则参数在开局前确认并锁定版本；游戏内改判通过理由与补偿表单；日志页保存／载入／导出场次；PL侧提交建卡、计划、骰子、防御、转交、卡片、交涉和结局。安装服务不属于玩家操作，但开局与游玩不得以终端命令代替前端入口。导入／载入先预览校验，载入既有场次需暂停并明确确认，不把浏览器本地导出当作在线权威状态。

### 浮窗行为

- **W-KP-QUEUE**：KP默认展开于右侧，按待处理／等待PL／可结算分组；点击待办只定位主分页的对应裁定，不立即掷骰或结算。当前处理对象不因新消息自动切换。折叠为带未读数的标题条；关闭后工具栏仍有队列入口，不删除待办。
- **W-CHAT**：可切公共／队伍／KP私聊子页签，受众常驻；未发送草稿按频道分开保留。未读在折叠态累计，不能自动抢焦点。
- **W-BAG／W-CHARACTER／W-DETAIL**：可停靠左侧或右侧，卡面与状态只读查看不阻塞主要行动；仅提交使用或转移时执行游戏操作。
- **W-CARD-EDITOR**：纯文字标题、正文、可选附件和受众；道具卡从真实实例预填名称／数量，PL可填描述但不能改真实数值；KP审核仍存在。保存草稿、关闭、重新打开均不扣游戏资源。
- **确认对话框**：只用于丢弃、载入覆盖、最终选择等需要当场确认的动作，一次最多一个；普通聊天、日志和队列都不是全屏模态。满包时可从领取框打开背包，不形成互相遮挡的模态链。

浮窗在工作区边界内拖动与缩放，可折叠、停靠、恢复；标题条始终可达，至少保留主操作区。提供“整理窗口／恢复默认布局”按钮，浏览器缩放或视口变化后将超界窗移回可见区。浮窗层级只影响阅读顺序，不改变游戏状态；Esc不能取消已提交请求。切内部分页保留窗口和草稿；只有明确退出房间才清理该房间UI状态。

### 状态分层

窗口坐标、折叠、停靠、主分页、各分页滚动位置和筛选是个人UI偏好；按账号／角色／房间隔离。私密正文不写入共享布局缓存，退出或身份切换清除内存中的旧投影。动作、费用、库存、裁定与待办是权威会话状态，不随隐藏或关闭窗口回滚。请求尚未返回时可收起窗口，但按钮显示处理中；恢复后查询原operationId，不能再发一份操作。

桌面验收增加：仅开一个标签页完成KP开局和PL入场；三个工具窗并列时仍可操作；KP队列切图／切日志后保持过滤和当前对象；折叠聊天不漏掉待处理提示；关闭待办窗不取消任务；恢复布局不重发请求；非当前页的事件只更新角标，不把PL强行带到其他分页。
