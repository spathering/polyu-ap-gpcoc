## 1. 启动与连接

先使用宿主自己的入口启动房间，再运行 `dist/RoomManager.exe`。输入地址、账号和密码后点“连接”；首版接受 `http://127.0.0.1:端口` 或 `http://localhost:端口`，不接受路径、远程地址、URL 凭据或跳转。KP 账号可以管理，玩家账号会被拒绝。登录后密码输入被清空，Cookie 与 CSRF 只在内存中。

顶部分别显示 WS 样本时间和管理数据获取时间，两者不是跨接口原子快照。管理接口默认每 2 秒刷新。断线禁用命令提交，恢复后建立新观察段；权限失效清理管理数据并要求重新登录。关闭工具不停止宿主。

左侧选择数据类别并搜索，右侧查看只读原始 JSON 和编辑表单。列表按键排序，每页最多呈现 500 项，上一页/下一页只切换已收到的数据；这是本地分段，不是宿主分页查询。概览包含房间、目录、运行及存储摘要。普通实例列表只包含当前可见的活跃实例。

### 登录成功但一直等待快照

地址必须指向真实宿主，不能仅凭网页能登录或 capabilities 返回协议 1 判断连接完整。配置包网页入口可能只转发 HTTP，不转发 WebSocket。当前 `mini-detective-pack` 的默认网页入口为 8888；其启动器默认另分配一个随机端口运行宿主，因此管理器连接 8888 时可能登录成功，但 `/api/v1/connect` 升级请求返回 404，随后持续重连。

处理方式：点击“断开”，把地址改为当前宿主端口，再以 KP 账号重新登录。宿主进程的启动参数为 `engineering/backend/scripts/run.py ... serve --port <端口>`；应确认对应房间的数据目录，避免选中其他房间。配置包重启后随机端口可能改变。配置包启动器支持 `--backend-port` 指定固定宿主端口，但不要为了调整端口直接终止正在游玩的房间。

2026-11-05 已对正在运行的网页入口和对应宿主做无凭据握手核查：网页入口返回 404；真实宿主进入 WebSocket 认证检查并返回 403。这里的 403 是匿名探测的预期结果，不表示有效 KP 登录后仍会被拒绝；该核查没有读取凭据、修改房间或替用户登录。

## 2. 编辑数据

先选中对象，再选择操作。带 `*` 的字段必填；可选字段只有勾选后才提交。字符串、枚举、布尔值有独立控件，数值表、标签、规则绑定等结构字段使用局部 JSON 输入框。可以查看未知字段，但表单不会写回整个原始对象。

| 对象 | 操作 | 说明 |
| --- | --- | --- |
| 配置 | `configuration.put/remove` | 新增或修改需填配置 ID、修订、类型、默认值；修改内容使用新修订。默认值改变不迁移既有实例；被引用的配置不可删除 |
| 实例 | `entity.create/patch/update/archive` | 按配置创建；patch 改名称；update 改数值、标签、归属、可见性或规则；archive 为归档，存在关系引用则拒绝 |
| 关系 | `relation.set/remove` | 新建关系、移除关系；不提供关系原地修改 |
| 进度 | `progress.set` | 根据 ownerKind、ownerId、eventKey 设置 JSON 值；不提供删除 |
| 成员 | `member.update` | 修改现有成员的启用状态、角色；不能移除最后一个有效 KP；不创建账号或修改密码 |
| 房间 | `room.status` | active、paused、archived，由宿主解释和校验 |
| 流程 | `flow.respond/cancel/retry` | 等待列表提供 waitId/revision；回应为布尔值。retry 是新尝试，可能重新掷骰，只适用于宿主允许重试的流程 |
| 素材 | 上传、下载、`asset.attach/remove` | 上传可选 public/kp，最大 10 MiB；挂接实体；只允许移除无引用登记 |

例如改角色 HP：选中 `entities` 中的角色，选择 `entity.update`，勾选“数值表 JSON”，填 `{"hp": 8}` 后提交。该操作合并数值表，不删除未写入的数值。归属字段可填账号 ID；填 `null` 清除归属。标签使用 `["melee"]`，行为绑定使用 `{"attack":{"ruleId":"规则ID"}}`，实际有效性由宿主检查。

实体编辑保留开始编辑时的 viewToken。收到 `VERSION_CONFLICT` 后草稿不变，点“比较最新值”查看开始编辑时的值、当前样本和草稿；决定继续时点“重建编辑基线”，再重新填写修改项并提交。自动刷新只更新列表和详情，不替换草稿中的旧版本令牌。

配置、关系、成员、进度等标注“无原子版本保护”。对选中对象的提交会先重读比较，但刷新和提交之间仍可能被其他人修改；这不等同于实体的版本校验。每次提交只执行当前一个操作，底部显示 committed/rejected/pending 或公开错误码。

## 3. 规则文件

“导入完整规则组”一次选择所有 Lua 文件和 JSON 数据文件，文件名作为键填入暂存表单；同名文件拒绝导入。当前为扁平文件组，不自动递归导入目录。导入只改变本地草稿，提交 `rule.stage` 才由宿主校验并产生修订。

在 `artifacts` 列表选修订并点“查看规则源”，可查看文件内容、数据及相对当前激活修订的 sourceChanges/dataChanged。确认后选择 `rule.activate`，填写完整修订并确认激活。回退同样是激活旧修订。暂存失败保留旧版本，既有流程锁定的规则版本仍由宿主管理。

## 4. 观察与关注

“观察到的变化”按 view/admin 分别比较样本，第一份数据只建立基线。记录包含观察 ID、观察段、接收时间、类别、对象 ID、字段路径、前后值、来源修订（若提供）以及关注是否命中。`beforePresent/afterPresent` 区分缺字段与 null；数组整体比较，viewToken 和运行指标不进入业务差异。

选中对象后，在关注路径框填 `/numbers/hp` 等路径并点击“关注选中对象/路径”；留空表示整个对象。路径按 JSON Pointer 转义，`/` 写成 `~1`，`~` 写成 `~0`。在“关注”列表中可启用、禁用或删除，观察页可勾选“仅关注的变化”。关注定义按宿主地址、账号、roomId、runId 隔离。

对象从投影消失标为“不再可见”，并不据此判断删除。WS 和管理轮询可能省略中间态，断线后无法补齐；重新连接会清空旧样本、建立新段并提示缺口。宿主最近 100 条审计在独立类别中查看，不按相近时间把审计操作者强行配给样本差异。聊天仅能通过概览查看频道元数据，工具不管理聊天正文。

默认最多保存 2000 条观察、100 项关注；观察另有 16 MiB 的 JSON 估算字节上限，达到任何上限淘汰最旧记录，页面显示淘汰数。观察前后值只在内存中，退出或权限变化即清理。

## 5. 回执与备份

结果未知时先查询当前 commandId 的回执；在明确结果前，界面阻止生成新 commandId 重做。当前会话保留的“原封套重发”使用相同 commandId 与参数，不会自动生成新的业务命令。重启工具后，在“命令记录”选择记录并查询；只保存最小查询元信息，因此不能恢复原参数并重发。重连、身份或 authority 变化会清理旧封套。未知回执不等于命令未执行。

“创建备份”请求宿主生成备份并显示 backupId，不含身份库；文件位于宿主侧。首版没有备份列表、下载、删除、恢复或热切换。备份与上传没有 commandId 回执，超时可能已执行，工具不会自动重试。尚有请求进行中或命令结果未知时，退出会提示。

## 6. 本地设置与部署

复制整个 `dist/` 即可部署，不要复制 `.test-output/`。`tool-config.json` 设置默认地址、管理轮询间隔（1000—60000 ms）、观察数（1—2000）、关注数（1—100）；启动时读取，配置错误会提示。`dependency-manifest.json` 说明框架要求，`release.json` 给出版本与 EXE 摘要。

默认设置在 `%LOCALAPPDATA%/OnlineCOC/RoomManager/settings.json`，仅保存关注定义和最近 200 项命令查询元信息，不保存密码、会话、完整参数和房间值。可用 `RoomManager.exe --settings-dir <目录>` 隔离不同工具实例的本地设置；同时运行多个管理器时建议分别指定目录，以避免覆盖彼此的本地设置。房间权限及命令并发仍由宿主处理。

中文素材名在 HTTP 头中采用百分号编码，宿主登记名称可能显示编码形式，下载对话框会解码文件名。工具不浏览、改写或清理宿主素材目录。
